# Notation-first DAW

A notation-first Digital Audio Workstation (DAW) that combines the score editing capabilities of MuseScore with the MIDI control and VST integration of traditional DAWs.

The project aims to build a tree-based music notation data structure with MusicXML compatibility. Each notation element can generate MIDI events or modify events generated by other elements through configurable rules, allowing articulations, dynamics, and other musical markings to directly control playback.

A TypeScript prototype worked out the data structures and the playback rules; the app itself is written in C++ with JUCE. The long-term goal is to support expressive, VST-driven music production entirely through traditional music notation.

## Concept
```
Music Data + Layout Data ──(Layout Strategy)──(Layout Overrides)──► rendered pages

Music Data ──(expand repeats, tag pass #)──► played order
  ──(Intent Profiles + playback directives in score)──► Musical Events
  ──(tempo map)──► Timed Events
  ──(individual overrides)──► 
  ──(Instrument Profile + library-specific tweaks)──► MIDI ──► VST
```

## Status

- `prototype-web/`: the TypeScript prototype, now the reference the C++ app was
  ported from. MusicData and profile types, MusicXML import, and playback:
  `pnpm midi` writes the scores, their playback setups (with every profile, which
  are TS code in `src/core/examples/`) and the MIDI the C++ tests compare with.
- `cpp/`: the native app (C++20, JUCE 8). See [cpp/README.md](cpp/README.md).
  - Engraving with its own layout (Leland, SMuFL): pages from `Layout.flow`, which
    changes only on a reflow.
  - Playback ported from TS, giving the same MIDI to the last byte on every
    exported score.
  - Editing: select notes and move their pitch, with undo; export MIDI.
  - VST3 hosting (ASIO, WASAPI): a plugin rack shared by every score, like a DAW
    template (Kontakt with Cinematic Studio and Symphony Series); playing from any
    measure, with a cursor, hearing edits while it plays.

Next: a profile editor in the app. Profiles become data the app owns: a library
shared by every score (`%APPDATA%\Musicsheet DAW\profiles\`, one JSON file per
profile, imported once from the TS profiles), with each score keeping only which
profiles its tracks use and its overrides. The editor changes the JSON and checks
it with the existing loader; a generic editor comes first, then views for
keyswitches, curves and note rules, with changes heard while the score plays.

Set aside for later: saving edited scores (a project file), per-score overrides of
the rack, hearing a note when it is moved, and drawing and editing dynamics,
articulations and techniques.
